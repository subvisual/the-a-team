# ateam-definition (stub)

**No-op placeholder.** The real definition skill is authored later by a PM against
`CONTRACT.md`. This stub only exercises the orchestration wiring.

Interaction mode: 📝 **draft + review** — it derives from approved JTBDs and is
reviewed at the orchestrator gate. It does not interrogate.

Given the feature directory `docs/features/<slug>/`, the product directory
`docs/product/`, and `feature.json`:

1. Read `prompt` from `feature.json`, plus `docs/product/context.md` and every
   file in `docs/product/jtbd/`.
2. Write `prd.md` in the feature directory:
   ```markdown
   # PRD (stub) — <slug>

   > Placeholder generated by the ateam-definition stub. Replace with the PM skill.

   **Prompt:** <prompt>
   **Jobs in scope:** <jtbd ids read, or "none found">

   TODO: problem, goals/non-goals, user stories, acceptance criteria, scope.
   Every scoped item must trace to a JTBD id.
   ```
3. Create `docs/features/<slug>/briefs/` with a placeholder `README.md` (the real
   skill produces the wireflow + per-screen requirements here).
4. If the orchestrator passed revision notes, append them under a `## Revision notes` heading.
5. Read the current `feature.json`, set **only** `phases.definition.status = "complete"`,
   preserve every other field (including `attempts`), write it back. Save.

Do not touch any other manifest field or artifact. **Never write to
`docs/product/`** — durable artifacts belong to discovery. Be idempotent —
overwrite `prd.md` cleanly if re-invoked, never append duplicates.
